# 开奖统计

本机用的开奖统计。从中国福彩官网拉福彩3D，从中国体彩官网拉排列三和排列五，按你保存的规则统计「近 N 期开了多少次」，并算出当前遗漏。点详情可以看到命中的期号、日期和号码。开奖查询页直接查本地库里已经同步的数据。

默认只监听本机。页面是 Vue 单页应用，开奖、规则、预测、回测和账号都从 `/api` 读取。数据存在项目里的 SQLite 文件中。

## 启动

需要 Node.js 22 或更高版本（用的是 Node 自带的 `node:sqlite`，不用额外安装数据库）。

```bash
npm run build
npm start
```

浏览器打开 http://127.0.0.1:3840 。端口可用环境变量 `PORT` 改。放到阿里云上的步骤写在 [DEPLOY.md](DEPLOY.md)。开发时可以另开 `npm run dev`，Vite 在 5173 并把 `/api` 转到 3840。

页面顶上可以在福彩3D、排列三、排列五之间切换。每个彩种第一次点「获取近 500 期」。之后点「同步最新」只补新期，同一期号以官网最新结果覆盖。点「向前补 500 期」继续往更早的历史补。三个彩种的规则和开奖互不影响。福彩3D、排列三、排列五各自只保留最新 500 期：每次同步成功后，以及服务启动时，都会按开奖日期从旧到新删掉多出来的期。自开3D不在这 500 期里，也不会被这次清理删掉。

服务启动期间会按北京时间每天 21:30、21:35……22:30 自动检查三个彩种。**每个彩种分别记录完成状态**：官网最新一期的开奖日是当天，才算该彩种完成并停止检查。官网最前面仍是昨天的号码时，继续检查到 22:30。每次同步成功后，以及服务启动时，会为该彩种最近 15 期里还没有存档的期号补一份预测。补档只用该期和更早的开奖，已有存档不覆盖。超级管理员可在「管理中心」查看每个彩种的最近检查和完成状态。定时状态写入 `app_meta`，依赖 Node 服务持续运行（阿里云部署由 systemd 保持运行）。

「开奖查询」顶上用和预测页一样的按钮切换福彩3D、排列三、排列五，切换后立刻显示该彩种。期号、日期、号码放在可折叠的「筛选条件」里。首页点「开奖查询」会带上首页当前彩种，查询页选中它并清掉上次留下的期号、日期和号码，直接显示这个彩种的开奖。之后在查询页里切换彩种，仍会记住筛选条件。可快速显示近 10、30、100 期，或分页浏览。号码按顺序匹配，输入 `398` 会找到含有 `3,9,8` 相连的期。查询页的彩种按钮不含自开3D，也不再提供「全部」。

「号码预测」先在页面顶部切换彩种。本期号码、专家推荐、存档核对和向前回测都跟着这个彩种变。综合算法会给每一注可能的号码打分：每位出现次数、和值、跨度、单双一起看，留下更像近几期整体开奖的几组，并且后一注至少改两位。复式从这些高分号码里收，每位最多 5 个号，默认 4 个。冷热对照仍保留。存档由服务在启动和同步成功后自动补上，不必每天打开预测页。具备网站操作权限的账号仍可在开奖前覆盖尚未开出的那一份；下一期入库后锁定。核对按开奖日期从近到远排列。这不能提高中奖概率。被授予推荐权限的账号可以在预测页提交专家推荐。

检查规则和同步逻辑：

```bash
npm test
```

## 页面上的口径

- 福彩3D 和排列三从左到右是百、十、个。排列五是万、千、百、十、个。0、2、4、6、8 是双，其余是单。
- 位置大小：0–4 小，5–9 大。和值大小：三位是 0–13 小、14–27 大；排列五是 0–22 小、23–45 大。
- 质数按 1、2、3、5、7，其余（含 0）算合。012 路是号码除以 3 的余数。
- 跨度是这几位里的最大值减最小值。
- 豹子、组三、组六、顺子只用于三位号码。豹子是三位相同，组三是只有两位相同，组六是三位都不同。顺子也算组六。
- 顺子：把三位从小到大排列后能接成连续数字（012 到 789），另外把 890 算顺子，不算 901。
- 连号：任意两个数字相差 1。0 和 9 不算连号。
- 一条规则里的条件全部同时满足才算命中。某一项不填，就不限制那一项。
- 次数和占比只看近 N 期。当前遗漏从该彩种库里最新一期往前数，不受 N 的限制。最新一期就命中则遗漏是 0；库里从没出现过则显示「库内未出现」。

当前彩种记在浏览器 `localStorage` 的 `lottery.code`。每个彩种自己的近 N 期记在 `range.fc3d`、`range.pl3`、`range.pl5`。预测页每位取几个号记在 `predict.k.<彩种>`，默认 4。查询页的筛选和近 N 期显示偏好保存在 `draws.filters`、`draws.recentLimit`。

号码预测只使用已经入库的开奖，排序不能提高中奖概率。综合预测枚举该彩种的全部号码：福彩3D 和排列三是 1000 注，排列五是 10 万注。近 N 期里越新的开奖权重越大，`RECENCY_HALF_LIFE` 默认 20，也就是大约每 20 期权重减半。每位次数、和值、跨度、单双都做了平滑，某个号在近窗里没出现也不会被判成不可能。和值、跨度、单双的权重在 `src/predict.js` 顶部的 `SUM_WEIGHT`、`SPAN_WEIGHT`、`PARITY_WEIGHT`。直选最多 8 组，后一注和已选的每一注至少差两位。复式按分数从高到低收集数字，每位收到 K 个就停，K 为 1–5。

冷热对照不参与综合打分。热号是近 N 期次数多的号，次数相同则遗漏小的在前。冷号是遗漏大的号，这个位置从没开过的最冷。遗漏从该彩种最新一期往前数全部在库数据。

向前回测在单独一页。它按时间从旧到新，预测某一期时只用更早的开奖，再和这一期的真实号码比。最前面的 N 期只作依据，剩余可用开奖是实际核对期数；结果会显示核对日期范围。复式命中表示开奖号每个位置都在对应选号集合中，直选命中要求号码完全一致。随机理论期望按每期实际注数占全部号码空间的比例计算，是同注数随机选择的平均次数，不是另一套预测算法。五种算法一次计算，切换不重算。盈亏区按输入的 1 倍奖金和倍数估算，还会显示按本次命中保本所需单倍奖金；这些历史结果不代表未来。排列五要逐期算完全部号码，只有超级管理员可以回测。

「模拟试玩」仅对有试玩权限的用户开放，彩种包括福彩3D、排列三、排列五和自开3D。选号页先点「添加选号」，把当前一组完整号码放进明细并清空选号区，页面留在选号处，可以继续添加下一组。点「选好了」才进入明细下注；如果选号区里还有一组已经选完整的号码，会先补进明细再打开。号码没选全、余额不足、倍数不合法或开奖数据缺失时留在选号页并提示。每注 2 元乘倍数，从模拟余额扣除。官方彩种的订单在该彩种截止时间前可撤销。自开3D只属于当前账号：可以先下多注，未开奖前能撤单；点「开奖」后由服务生成 000 到 999 中的一个号，并兑掉这些未开奖的注。单注奖金默认 1040 元，中奖后再乘倍数。模拟返奖为固定估算，不是真实派奖。超级管理员可在试玩运营台按所选用户删除其自开3D订单和开奖，未兑奖的注先退回余额。

超级管理员可从顶部「管理」进入管理中心，查看账户、模拟试玩和各彩种自动同步状态；「试玩运营台」可搜索用户、设置余额、修改截止时间，并按用户名、彩种和状态筛选订单。订单列表展示最近 300 笔。新建用户的初始密码由超级管理员设定，首次登录必须先修改。重置密码时由系统生成临时密码，只在页面上显示一次，对方现有登录会立刻失效。用户自己修改密码后，其他设备上的登录也会退出。登录会话最长 12 小时；密码连续输错 3 次后要求图形验证码。

超级管理员只能有一个；角色只能新增「管理员」或「查询」，试玩权限可独立开关。查询角色只读，管理员可管理开奖同步、规则和预测；只有超级管理员能管理用户、角色、清理数据和试玩运营。清理数据按开奖记录、预测存档、统计规则、试玩余额、普通用户/自定义角色、订单等分区操作，每区都显示影响数量并要求二次确认。

顶部主题按钮可切换经典紫、体彩红金、福彩蓝金、翡翠绿和喜庆中国红。主题按登录账号保存在当前设备，不改变其他账号的设置。页面采用响应式布局，可在手机浏览器及 iPhone 内嵌浏览器使用；非首页另有应用内「返回」按钮，浏览器或手机系统的返回操作也会沿页面历史返回，直接打开深层链接时应用内按钮会回到对应上级页面。

## 数据库

文件在 `data/app.sqlite`。测试用的临时库走环境变量 `FC3D_DB`，不会碰到这份正式数据。

`draws` 存官网开奖。唯一键是 `lottery_code + issue`。福彩3D 期号像 `2026300`，体彩期号像 `26300`，即使数字撞上也不会互相覆盖。三个官方彩种各保留最新 500 期，超出的从最旧一期删起。`self_draws` 另存每个账号自己的自开3D开奖，不参与这 500 期，也不进入官网同步和预测。

| 字段 | 含义 |
| --- | --- |
| `lottery_code` | 彩种。`fc3d` 福彩3D，`pl3` 排列三，`pl5` 排列五 |
| `issue` | 期号 |
| `draw_date` | 日期，`YYYY-MM-DD` |
| `digits` | 号码，逗号分隔。三位是 `3,9,8`，排列五是 `3,9,8,7,0` |
| `extra_json` | 扩展位。现在放 `week`、`sales`、`source`。再加字段不用改表 |
| `updated_at` | 这一行最后一次被写入的时间 |

排列三入库用官网的 `lotteryDrawResult`。不要用 `lotteryUnsortDrawresult`，那个字段会带上排列五的后两位。

`rules.definition` 是规则条件的 JSON，按 `lottery_code` 分开。`sort_order` 越小越靠前，新建的规则会排到最前。

`sync_log` 是每次同步的结果。`app_meta` 记「预设规则是否已经种过」和「官网总期数」。删光规则再重启，不会把预设再插回来。

`forecasts` 存预测存档。每个彩种的每一期最新开奖只留一份，唯一键是 `lottery_code + based_issue`。`payload` 里是当时的综合直选、综合复式、冷热直选、热号复式和冷号复式。下一期开奖不写进这张表，核对时用比 `based_issue` 更新的那一期现算。自开3D没有预测存档。`expert_picks` 按账号、彩种和依据期号保存专家推荐，只有 `users.can_recommend` 为 1 的账号可以写。

## 规则 JSON

页面保存前会先收成下面这种形状。空着的项不会出现。排列五没有 `shape`。

```json
{
  "positions": [
    { "parity": "odd", "size": "big", "prime": "prime", "road": 1, "digits": [1, 3] },
    {},
    { "parity": "even" }
  ],
  "sum": { "min": 10, "max": 18, "parity": "odd", "size": "big" },
  "span": { "min": 2, "max": 7, "parity": "even" },
  "shape": "group6",
  "oddCount": 2,
  "bigCount": 1,
  "contains": [1, 9],
  "excludes": [0],
  "consecutive": true
}
```

`positions` 的顺序跟 `src/lottery.js` 里的 `positions` 一致。`parity` 取 `odd` / `even`，`size` 取 `big` / `small`，`prime` 取 `prime` / `composite`，`road` 取 0、1、2。`shape` 取 `leopard`、`group3`、`group6`、`straight`。`consecutive` 为 `true` 表示必须有连号，`false` 表示必须没有。

要改开局就有的那几条规则，改 `src/rules.js` 里的 `presetRules`。已经种进数据库的不会自动更新，需要在页面上改，或者删掉 `data/app.sqlite` 后重新同步。三位彩种的预设是单单双、双双双、豹子、组六、顺子、和值大。排列五的预设是全双、全单、和值大、有连号。

## 接口

都在 `server.js` 底部的路由里。除了登录和退出，接口都要先登录。超级管理员可以管理角色和用户、清理数据及管理试玩。普通「管理员」角色可操作开奖同步、统计规则和预测；「查询」角色只读；试玩权限另行配置。用户创建或密码重置后的临时密码必须在首次登录时修改。会话最长 12 小时。首次启动会创建账号 `admin`，初始密码写在 `data/admin-initial.txt`。

带 `lottery` 的地方可传 `fc3d`、`pl3`、`pl5`，不传时统计和同步默认福彩3D。

| 方法 | 路径 | 作用 |

| POST | `/api/login` | 正文 `{ "username", "password" }`。同账号或 IP 连续失败 3 次后需提交图形验证码；成功后写入最长 12 小时的登录 cookie |
| POST | `/api/logout` | 退出 |
| GET | `/api/me` | 当前账号。未登录返回 401 |
| GET/POST | `/api/admin/roles` | 超级管理员查看、添加普通角色。角色类型为管理员或查询，试玩权限可单独配置 |
| DELETE | `/api/admin/roles/:id` | 删除自建角色。内置角色、还有用户的角色不能删 |
| GET/POST | `/api/admin/users` | 超级管理员查看、添加用户 |
| PUT | `/api/admin/users/:id/password` | 超级管理员重置普通用户密码；用户下次登录必须修改 |
| DELETE | `/api/admin/users/:id` | 删除用户。不能删自己，也不能删掉最后一个超级管理员 |
| GET | `/api/admin/sync-status` | 管理中心查看今晚按彩种分别记录的自动同步状态 |
| GET | `/api/admin/data-summary` | 超级管理员查看分区清理前各类数据数量 |
